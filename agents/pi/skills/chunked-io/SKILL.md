# chunked-io — 分段 IO 纪律(治标层,根修在代理链侧进行中)

**为什么(长期有效)**:当前链路(goswitch→LiteLLM→Anthropic)在【会话上下文大 × 工具
调用参数大】组合下会静默截断/断流(terminated 反复重试;流式非流式皆然)。上游 goswitch
为第三方**不可修**(环境顾问调查报告:kiwiai-dev-env/task_cards/INVESTIGATION-20260724-
nginx-toolcall-truncate.md),故本纪律为**长期执行策略**,链路更换或上游修复后由顾问重估。
实测边界:合成单条探针 157k 完整/188k 必断;**真实多轮满工具会话 111k 即有死例**——
阈值按真实死例保守取。小参数调用在大上下文下安全(~5KB@188k 完整)。

## 规则

1. **读:按需分段,绝不整读大文件**
   - 先 grep/定位再读目标行区间;单次读 ≤300 行;
   - 已读过的内容不重复读(要点自己记住);大文件禁止"再看一眼全文"。
2. **写/编辑:大内容一律拆段,单次 ≤100 行(≈4KB)**
   - 新文件:首段 write ≤100 行,其余分多次追加(append/边界清晰的小 edit);
   - 改文件:一个大重构拆成多个小 edit(每个 edit 的新文本 ≤100 行),按依赖顺序逐个提交;
   - 每段落盘后自检(读回边界几行或跑轻量校验)再写下段。
3. **上下文预算**
   - 动手大改动前看状态栏:上下文过 ~80k 且还有大量工作 → 先 /compact(或把剩余工作
     block-and-report 给顾问拆卡);
   - 探索期节制:能用 grep 回答的不读全文,能记住的不重读。
4. **失败协议(遇 terminated)**
   - 同一写入**不许原样盲重试**;将该段减半再试一次;
   - 减半后仍败 → 按 `block-and-report` 停(附:当时上下文规模、目标写入大小、重试记录)。

## 边界

- 上游第三方不可修 → 本纪律**长期有效**;链路更换/上游修复后由顾问重估阈值。
- 配套的 harness 层钳位(能力表 contextWindow 下调触发 pi 自动压缩)另行由 Owner 拍板。
- 不改变任何红线:车道、授权、验收准绳照旧。
