# write-return — 如实汇报结构

每张任务卡收尾(完成 / 部分完成 / 中止 / BLOCK)都按此结构汇报。**汇报的价值在于可核对,
不在于好看。**

## 结构(按序)

1. **一句话结论**:完成 / 部分完成(完成了什么没完成什么)/ 中止(停在哪)。
2. **做了什么**:动作级清单(不是感想)。
3. **改动清单**:文件路径 + 改动性质;有 commit 则附 hash。
4. **测试/验证结果原文**:命令 + 输出摘录,**引原文不转述**;没跑就写没跑、为什么没跑。
5. **排除物 + 理由**:决定不做/不提交的东西,逐项说明。
6. **异常与自作判断**:何处偏离了卡、依据什么判断、影响面。
7. **实际使用的模型 + 自报 token 用量**(能力账本进料,格式:`model=<provider/model>,
   tokens≈<in/out>`;多模型分段报)。**模型字段必须抄运行时指示**(pi 底栏显示的模型名 /
   claim 时 `-model` 的值),**禁止凭自我认知填写**——模型对自身身份的感知不可靠
   (实案 2026-07-24:sonnet-5 会话自报 "claude-sonnet-3.5",session 记录证伪)。
8. **待办 / 移交**:留给下一棒(顾问/Owner/审计)的明确事项。**回报最后一行必须是
   "下一棒粘贴行"**——下一动作的完整可粘贴命令(绝对路径),如:
   `下一棒:auditor 跑 → /claim /home/kiwi/projects/lybra/task_cards/<卡号>/AUDIT-<卡号>.md`
   (Owner 不该翻文件找路径;实案 2026-07-25:回报未报审计卡位置,Owner 无法直接接力)。

## 红线

- 失败如实报;禁止"应该没问题/大概率成功"这类不可核对表述。
- 测试输出与数字必须可复核;粉饰 = 事故。
- 不写入任何治理档/台账——汇报交给会话与卡指定出口,落笔归顾问。
