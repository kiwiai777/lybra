# task-closure-loop — 任务闭环(标准工序)

**一句话**:每个实现类任务都走同一个闭环——执行者干活并写报告,审计者独立裁,
修复循环有界,审计 PASS 后由产品收账。项目是什么协作拓扑(串行/星型)不影响本工序。

**落点**:一个任务的全部工件(报告 / 审计报告 / 修复报告)落在**卡面声明的落点**
(卡面「报告落点」给出的绝对路径及其所在任务目录)。任何角色不得把任务工件写到卡面声明之外,
也不自选目录。

**门动作归产品**:认领、派审、裁决落账、finalize、deploy、close 一律由驱动方经产品完成;
执行体 / 审计体只写产物,报告落盘即止。Owner 真人核验只在卡面声明 `owner_verify` 时插入
(PASS 后、收账前)。

```
顾问出卡 → 驱动方经产品认领 → executor 执行 + write-return(写到卡面落点即止)
 → 产品派生审计卡并派审 → auditor 独立审【准绳=原执行卡】→ 报告写到审计卡落点即止
 → 驱动方经产品落裁决:FAIL → F-* 打回修 → 复审(有界) / PASS → 产品收账
```

## 各角色工位

**executor(你若是执行者)**:
1. 执行原卡 → 按 `write-return` 汇报,报告写到卡面声明的落点,写完即止;
2. 审计卡由产品派生,执行者不写审计卡、不派审;
3. 被打回时:**只修 F-* 清单项 + 回归**,不趁机扩面;修完照修复卡声明的落点重写报告,写完即止。

**auditor(你若是审计者)**:
1. 全程按 `audit-independent-evidence`;**核验清单自己从原执行卡提取**,派生审计卡与执行者报告里的
   任何转述仅供定位,不作准绳;
2. 首轮=全量核验;复审轮=F-* 修复项逐条 + 回归抽查(防修 A 坏 B);
3. 结论三值:PASS / PASS_WITH_NOTES / FAIL(附 F-* 清单),写进审计卡声明的报告落点,写完即止;
4. **轮次纪律**:同一任务你已发出 **2 轮 FAIL** 后第三轮仍不能 PASS → 在报告中写明僵持点,
   交顾问仲裁,不再自行循环。

**顾问(工位只有三点)**:出卡、仲裁(BLOCK / 审计死锁 / 范围漂移 / 验收歧义)、
监控产品驱动的自动循环。不在执行↔审计之间充当串行工位。

**Owner(授权门)**:发布批准独立于审计 PASS——审过≠可发布;可经预授权信封把
某类小片的收账整批授权(授权即身份语义)。

## 红线

- 审计准绳=原卡,任何人不得用转述替代;
- 修复循环有界(默认 2 轮 FAIL 上限),僵持升级不空转;
- 实现批准与发布批准是两个门,永不合并;
- 纯文档/纯治理类任务可在原卡声明免审(Owner 直接过目),声明必须显式。
