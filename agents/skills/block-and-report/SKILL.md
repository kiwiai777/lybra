# block-and-report — 遇阻即停标准动作

**原则:宁停勿猜。** 停下来汇报永远不是失败;猜着继续才是事故。

## 必须停的情形(任一命中即停)

- 基线 / hash / 状态与卡描述不符;
- 文件或改动来历不明,无法溯源;
- 卡内信息不足以**无歧义**执行下一步;
- 护栏拦截(护栏是保险,不是试探边界的理由);
- 下一步会超出卡声明的车道或授权;
- 必跑测试红且原因不明。

## BLOCK 报告结构

1. **停在哪一步**(对应卡内步骤编号);
2. **现象与证据**:命令 + 输出**原文**;
3. **已排除的解释**:试过什么、排除了什么(只列已证实的);
4. **候选路径**(如有):每条附代价与风险,**不自选**;
5. **需要谁的什么决定**:明确点名(Owner / 顾问 / 环境顾问)。

## 报告必须落盘(会话会死,文件才是真相)

BLOCK 报告**先写文件、再贴会话**:落到该任务统一目录
`task_cards/<ID>/BLOCK-<n>.md`(n 从 1 递增,不覆盖旧报告);会话里只贴指路
(文件路径 + 一句现象)。**只写在聊天里的 BLOCK 报告等于没写**——会话随时被清,
仲裁者和续作会话都靠这个文件冷启动(2026-07-26 实案:finalize BLOCK 报告只活在
会话里,会话清掉后险些丢账)。文件末行 = 给仲裁者(顾问)的粘贴行。

之后**等授权**。不试探性继续、不部分执行、不"先做了再说"。仲裁结论会以卡的修订
或仲裁注记形式落盘;续作会话(哪怕原会话已清)以卡 + BLOCK 文件 + 仲裁注记冷启动。

## 红线

- 绕过护栏 = 事故;伪造/跳过校验 = 事故;
- 报告不夹带未经证实的归因(可以列假设,须标明是假设);
- 停了之后擅自重试同一动作 = 没停。
